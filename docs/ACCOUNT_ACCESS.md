# Public / Private 账号与访问

状态：当前实现与接入说明。
最后核验：2026-10-14。
权威范围：登录、注册、组织授权、密码管理、会话隔离及双环境部署。
数据来源：identity 服务、账号界面、自动化回归和本地运行验收。
替代关系：补充部署指南；替代原先仅支持管理员初始化、没有注册入口的账号流程。

## 入口与使用流程

登录页保留 BigoBio 品牌，显示 Public / Private 入口、当前环境、语言切换、登录与注册。未登录访问项目页会记录站内目标路径，登录成功后返回；禁止跳转至外站。登录后从用户菜单或设置进入「账号与访问」。

| 功能 | Public | Private |
| --- | --- | --- |
| 注册 | `open`：自行注册，建立独立组织，初始没有他人项目 | `invite`：管理员指定用户名、组织、查看者或研究员角色 |
| 登录 | 当前 Public 数据库中的账号 | 当前 Private 数据库中的账号 |
| 加入团队 | 管理员发放组织邀请码 | 管理员发放组织邀请码 |
| 改密 | 核对当前密码并确认新密码 | 同左 |
| 忘记密码 | 联系本环境管理员核验身份，获取一次性恢复码 | 同左 |

邀请码绑定用户名、组织和角色，默认只读，可选择研究员；有效期 1–168 小时，默认 24 小时。管理员只能邀请新账号；给已有账号增加组织成员关系仍通过组织管理完成。用户不能通过注册请求指定管理员角色或组织 ID。

查看者邀请同时设置账号级只读上限。该账号在当前部署的所有组织中保持只读；组织成员接口试图授予它研究员、管理员或所有者时返回 `409 account_read_only`，不会显示升级成功却仍无法写入。现有版本没有账号级角色晋升界面；发放邀请前应按真实职责选择角色。此限制保留既有全局权限约束，后续晋升功能需要独立的管理员授权、会话撤销及审计。

恢复码只用于已有本地密码账号，最长有效期一小时。完整代码仅在生成时显示一次，列表只保留状态和有效期；可随时撤销尚未使用的代码。界面明确当前部署不会发送恢复邮件。无邮件服务时不展示虚假的「邮件已发送」。

修改/恢复密码后所有旧 access token、refresh session 和此前生成的恢复码失效。普通退出撤销当前刷新会话族并清除浏览器认证及项目缓存；已被复制出去的短期 access token 仍受其到期时间约束。其他设备不因普通退出而退出。管理员初始化命令重置已有密码时同样提升凭证版本并撤销全部刷新会话。

## 环境隔离

两套部署共享代码和界面，账号与数据分别保存；这是统一入口，不是 SSO。切换入口只打开另一环境的登录页，不携带令牌、密码、项目 ID 或邀请码。数据库、JWT 密钥、Redis 命名空间和账号 realm 必须分离。不要以 Public 的用户表直接连接 Private 研究数据。

JWT 绑定 realm 和用户凭证版本；refresh cookie 按 realm 命名，避免同一主机不同端口覆盖登录。配置入口后，认证接口拒绝来自另一门户的浏览器 Origin；本地开发允许同端口的 localhost / 127.0.0.1 别名。CORS 设置也应只列出本环境可信前端。正式运行必须 HTTPS，Secure + HttpOnly cookie；开发模式仅用于回环地址。

默认注册关闭；Private 配置 `open` 会在启动时失败。只读部署关闭注册/改密/发码，保留登录、刷新及退出。注册与恢复有 IP 配额，登录有 IP + 用户名配额；生产需保持限流开启，反向代理必须正确处理可信客户端地址。邀请码和恢复码只存 SHA-256 摘要，不进入审计载荷；认证错误不回显密码和代码。

## 部署配置

| 变量 | Public 示例 | Private 示例 |
| --- | --- | --- |
| `BDA_V2_DEPLOYMENT_KIND` | `public` | `private` |
| `BDA_V2_AUTH_REALM` | `public` | `private` |
| `BDA_V2_REGISTRATION_MODE` | `open` | `invite` |
| `BDA_V2_PUBLIC_PORTAL_URL` | `https://public.example.org` | 同左 |
| `BDA_V2_PRIVATE_PORTAL_URL` | `https://private.example.org` | 同左 |

入口必须为纯 origin，不含账号、查询参数、片段或业务路径。本地 HTTP 仅接受回环地址。Compose 通过 `.env`，Helm 通过 `config` 对应字段配置。沿用现有数据库连接和密钥，不把部署密钥写入仓库。

升级前备份各自数据库；执行 `alembic -c backend_v2/alembic.ini upgrade head`，再启动同一代码版本。本地双环境升级仍暂停 API 和相关 worker，以便核验业务数据。`0075_account_access` 增加账号代码表以及 refresh family / realm；`0076_account_audit_compat` 增加兼容旧版写入的 family 数据库默认值，以及账号审计的限定 INSERT 策略。现有项目、用户和密码保持不变。切换 realm 后旧会话需要重新登录。

Helm 的迁移 hook 必须运行到完整 `head`。从 `0074` 升级时，两个迁移由 PostgreSQL 在同一个事务中提交，旧 API 不会见到缺少默认值的中间状态；迁移完成后旧镜像仍能插入刷新会话。不要只部署中间版本 `0075`。这保证旧式数据库写入兼容，不保证旧镜像支持新账号功能或新 realm；回退前仍须检查应用配置和会话边界。

生产应用使用无 `BYPASSRLS` 的数据库角色。注册、改密和恢复只有在凭证核验完成后，才临时设置专用于账号审计的事务上下文。策略只允许对应账号的三类审计 INSERT，不赋予匿名恢复请求项目访问权限，也不扩大审计读取、更新或删除权限。

迁移支持回退到 `0074_research_decision_contract`，但回退会移除邀请码/恢复码记录及刷新会话族字段；应先暂停写入、保存新版本备份，并明确放弃这些新增记录。仅降至 `0075` 会移除兼容默认值和账号审计策略，不是可持续运行的修复版本。应用数据库备份用于恢复，不应直接覆盖后续业务新增内容。

## 验证与后续扩展

自动化覆盖注册权限、组织隔离、重复用户名、邀请码过期/撤销/重复使用、角色注入、版本冲突、错误密码、恢复码失效、跨环境令牌/Origin、只读模式、并发消费邀请码、刷新与退出/改密竞态。前端覆盖注册、恢复、管理员可见性、撤销、跳转安全及刷新结束后不得恢复已退出账号。

### 对抗审查修复清单（2026-10-14）

| 问题 | 修复与验收依据 |
| --- | --- |
| 生产 RLS 阻止注册、普通用户改密和匿名恢复的审计写入 | 限定账号审计 INSERT 策略；以无超级用户/无 RLS 绕过权限的 PostgreSQL 角色验证，另检验越权读写仍被阻止 |
| 滚动升级后旧镜像无法写入非空 family 字段 | 数据库提供随机 UUID 默认值；验证旧式 INSERT、回退与再次升级 |
| 切换账号后复用旧的刷新请求 | 认证状态变化时取消旧请求并重新建立单次刷新；旧请求结束不能清除新请求 |
| 旧账号重试请求的迟到 401 清除新登录 | 重试结束再次核验认证代次；延迟响应回归测试验证新账号保留 |
| 调高只读账号组织角色返回成功但不能写入 | 返回明确 409，保留原成员角色，并在邀请界面说明账号级只读范围 |

这些测试补足原来 SQLite 和高权限数据库测试遗漏的生产权限及并发边界；自动审查记录不等同于 GitHub 的独立批准记录。

本次完整验证：后端 2,648 通过、7 个可选测试跳过，总覆盖率 90.18% 且核心覆盖门槛通过；前端 1,142 通过；浏览器矩阵 90/90。Ruff、mypy、类型检查、生产构建、公共数据隔离与文档/流程清单检查通过；前端 lint 无错误，保留 4 条既有库兼容警告。独立复核上述修复后未发现新的阻断问题。

这次不配置第三方身份提供商、SMTP、邮件地址验证、MFA 或跨部署单点登录。现有 OIDC 自动建号只允许开放注册环境；Private 不可借 OIDC 绕过邀请。后续如统一身份，应引入明确的 IdP subject 映射与每个环境独立的访问授权，并先处理账户关联、撤销和 MFA，再启用跨门户 SSO。
