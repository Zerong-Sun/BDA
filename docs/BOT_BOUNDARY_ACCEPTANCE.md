## 环境与方法

在实际入口 `http://127.0.0.1:5177` 使用隔离验收账号、两个合成 UI 项目和真实 API、PostgreSQL、队列、Worker、模型服务。资料只有 Bot 入口、决策/参数展示、工作区上下文三条 UI 笔记；所有任务没有写入授权，没有计算作业。浏览器实测没有拦截 API 或预置模型结果。组件和浏览器回归中的 fixture 与这部分实测分开记录。

本地后端基于发布版本 `e2389674e7d941b330e5cbd7e146e1f50c208c4c`，包含与当前源码不同的调用额度和重复提交保护。前端构建部署到原静态目录，保留旧哈希资源、最后替换入口，刷新浏览器验证。另向本地后端叠加本次取消修复的三个精确改动：每步交接 Worker、锁定后刷新运行记录、取消前按父子顺序加锁。备份后仅重启 API 和 copilot/research Worker；未覆盖其他后端差异，也未调整费用保护。健康检查恢复正常。

## 修复清单

- [x] **执行中取消被整段执行锁阻塞**：在模型调用已开始后点击取消，修复前请求超过 15 秒，任务最终完成，取消没有生效。Worker 现在每步提交并释放运行锁，再交接下一步；取消请求检查到达时的版本，获得锁后重新读取状态，避免使用过期对象写入或覆盖完成结果。已经发送的调用可能要先结束，界面明确显示等待确认。
- [x] **失败后没有方便的新尝试入口**：终止的标准任务可“准备重新尝试”，复制目标、补充要求、负责人、轮数、费用和已应用的方法到计划草稿；不自动执行，写入授权全部清空，保留原任务链接。零费用额度保持为零；没有应用方法时不偷偷改成默认方法。已有草稿须明确选择替换，其他项目草稿保持独立。
- [x] **继续执行承诺额外 12 轮与本地后端不符**：改为说明仅在剩余额度内继续，平台调用和费用限制仍生效。达到限制的 409 保留补充文字和已收窄授权；不会反复自动重试。
- [x] **继续请求提交期间仍可修改输入**：提交期间锁定文字和授权选择，阻止重复提交，避免成功回调清空用户在等待时新输入的内容；只读用户不能修改授权。
- [x] **相同任务被拒绝后缺少恢复说明**：本地后端会拒绝 24 小时内目标、负责人、工具及任务契约相同的任务，包括已取消任务；只调整额度也可能被拒绝。页面说明没有创建新任务、草稿已保留，提示检查已有结果或说明本次需要修正的内容。保留后端重复提交保护，不通过随机修改目标规避。

| 提交后立即取消 | `3e72ae98-816b-4fa3-bb0a-a557fe16444e`：取消返回 200，状态保持 cancelled，模型调用 0 次；没有“继续此任务”按钮 |
| 模型已开始后取消 | 修复后 `83f33692-71fc-4f83-bdb3-6d595b063195`：先通过独立持久台账确认已开始调用，再点击取消。605ms 后返回 200，最终 cancelled、3 条已记录消息、1 次模型调用；后续复查状态和调用数不再增长 |

台账记录的是调用准入预留，不是供应商账单。继续任务的最终预留为 CNY 0.548900，新尝试及其后续为 CNY 0.542868，执行中取消任务为 CNY 0.090370。取消不撤销已经发出的模型调用或费用。

本轮也观察到一次任务在等待可见过程消息时已完成，以及修复前一次执行中取消未生效；这些未计为取消成功。最终取消验收以独立调用台账、真实取消响应和延迟复查为依据。
