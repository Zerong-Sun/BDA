## 六个方面的结论

| 维度 | 核查内容 | 发现与处理 |
| --- | --- | --- |
| 需求完整性 | 用户能否从界面进入确定性计算；连续计算、混合查询是否完整交付 | 补齐研究室和抽屉的实验计算入口；保留多步计算、蛋白库结果和待补参数，不把一次计算成功等同于全部完成。 |

| 边界情况 | 额度耗尽、工具失败、截断、空内容、格式错误、无查询结果 | 保留成功结果，失败和跳过写入调用记录；部分完成可见且持久化；空蛋白查询明确显示无条目。 |
| 代码质量 | 计算规则重复、组件重复、工具边界和文档漂移 | 复用已有领域计算器与校验器；两个聊天入口共用 `ChatModeSwitch`；统一完成状态解析；更新服务和导航文档。未引入依赖、API 路由或迁移。 |

| 实际运行结果 | 真实模型能否经异步链路返回正确结果，页面能否实际使用 | 在已运行预览中完成两步计算；真实模型验证跨单位稀释、混合蛋白库查询、缺输入追问。运行中发现的单位问题与简报死链均修复。 |

## 修复清单

以下 11 项均已修复；“修复”指列出的具体缺陷与回归范围，不表示模型不会产生其他科学错误。

| 编号 / 优先级 | 触发方式与原问题 | 最终处理 | 验证 |
| --- | --- | --- | --- |
| A01 / P1 | 后端有专用 `wetlab-read`，前端从不发送该 skill，普通用户无法进入确定性交付路径 | 增加“研究问答 / 实验计算”，按项目保留选择；实验计算不自动转成研究任务，不带 bot 或章节审阅意图 | 聊天组件回归、实际研究室提交两步计算 |
| A02 / P1 | 模型只提供部分 A260/A280 条件时，服务端隐式采用空白、光程、稀释倍数等默认值 | 模型 schema 与执行入口均要求四项条件显式存在；缺项返回受控错误 | 四种缺项参数化测试；真实缺条件请求未执行计算 |
| A03 / P1 | 1 µM 原液与 10 nM 目标被按同单位比较，错误拒绝可行稀释 | 原液与目标单位分别传入，复用领域浓度换算后校验；结果附换算说明 | µM↔nM、mg/mL↔µg/mL、换算后仍不可行的反例；真实结果 10/990 µL |
| A04 / P1 | 同轮查询蛋白库并计算时，最终仅留下计算结果 | 两类工具结果都保存与展示；空结果明确说明；库名称按文本转义 | 混合查询回归；真实空库查询与计算均出现在同一回答中 |
| A05 / P1 | 同批工具调用超出额度，后续模型声明完成，界面丢失未执行范围 | 跳过的调用记录 `skipped`；预算状态强制降为部分完成 | 一次额度内提交两个调用的回归，验证模型 `complete=true` 不能覆盖跳过状态 |
| A06 / P1 | 工具已成功，最终模型失败、截断或空回复导致有效结果丢失；工具失败也可能被完成声明掩盖 | 保留已有结果、标注未完成、记录失败；消息保存 `delivery_status=partial` | 截断、模型异常、空内容、工具失败回归；完整/部分交付都不会再被措辞审阅改写 |
| A07 / P1 | 上游过滤或畸形工具调用可能被当正常响应接受，或在后续处理时崩溃 | 在提供方边界拒绝过滤输出，以及非数组、空条目、非法函数/参数、重复调用 ID 等无效形状 | 过滤输出及畸形调用参数化回归；原有截断检测继续通过 |
| A08 / P2 | 专用模式同时暴露新旧计算工具，旧工具结果无法进入统一计算交付 | 专用模式仅提供统一计算器和蛋白库查询；其他路径保留旧工具兼容 | 精确断言专用模式只提供两项工具，原有权限回归通过 |
| A09 / P2 | 模型用单个 Markdown JSON 代码块返回有效完成状态，被误判未完成；合成标注也可能污染控制消息 | 接受单个完整 JSON 代码块；严格校验字段、类型与问题长度；明确机器控制消息的格式职责 | 合法代码块通过，混杂正文仍降级；真实混合请求最终为完整交付 |
| A10 / P1 | “查看项目简报”及项目打开链接落在已经不展示简报的目标页 | 共用目标页任务书折叠区，`brief=1` 明确展开，普通目标页仍默认收起 | 默认/显式入口单测；生产构建浏览器中的项目打开、往返、刷新、只读流程 |
| A11 / P2 | 浏览器矩阵在文献数据仍加载时抓取焦点控件列表，页面就绪后列表失效，导致中文深色场景偶发失败 | 已填充文献场景先等待阅读导览可见，再执行完整焦点审计；不增加固定延时、不放宽断言 | 原失败场景单独重跑通过，再执行完整矩阵 |

浏览器验收脚本也同步到现有导航契约：实验工具只有独立入口，导览和 FAQ 位于唯一帮助菜单，目标管理需要显式展开。修复简报实际展示后才更新测试预期，未用删除断言替代功能修复。

真实模型使用用户指定的 `deepseek-flash`、非思考模式、温度 0.1、输出上限 4096。以下是小规模功能验收，不能用于模型排名、总体准确率或稳定延迟结论：

1. 在真实研究室选择“实验计算”，提交两步合成问题：dsDNA、A260=1、已扣空白、1 cm 归一化、未稀释；先得到 **50 ng/µL**，再配制 100 µL、10 ng/µL，得到 **20 µL 原液 + 80 µL 稀释液**。最终页面显示服务端公式与条件，输入框恢复可用。
2. 新对话仅提供 A260=1、样本类型及测量条件未知：模型追问必要条件，未调用 `calculate_bench`。该次异步链路耗时约 **4.10 秒**。
3. 蛋白库查询与“1 µM → 10 nM，终体积 1000 µL”同一请求：保留“查询无条目”，计算得到 **10 µL 原液 + 990 µL 稀释液**，持久化状态为 `complete`。该次链路耗时约 **4.09 秒**。

上述异步验收经过本地 API → 队列 → worker → DeepSeek → 注册工具 → 保存回答；没有创建实验记录。最终就绪检查中的 worker、调度器、数据库、Redis、MinIO 与 schema 均为 `ok`。模型仍会接收平台准备的项目只读上下文，“两项工具”指专用模式向模型开放的动态工具，不意味着没有其他平台上下文读取。

## 尚未覆盖和保留的边界

- 7 项跳过分别是：专用 Bot worker 并发环境 1 项、私有决策记录契约 1 项、需要显式开启的可丢弃 PostgreSQL 权限测试 3 项、未配置容器镜像的 gate runtime 集成 2 项。它们不计入通过数量。
- 后端全量运行出现 1 条测试环境 SQLite 连接资源警告；前端保留 4 条既有库兼容警告。二者均如实记录，不能写成“零警告”。
- 必填参数可防止隐式默认值，不能证明模型没有自行猜测字段，也不能检测所有语义上的单位误读。重要计算仍应核对显示的输入、单位和假设。
- 任意工具失败后，当前回合保守标为部分完成，即使模型之后重试成功；没有实现能证明每个失败步骤均已替代的任务匹配器。
- 完成状态通过严格结构校验，服务端可否决已知错误/预算跳过；仍不能证明模型已识别任意自然语言请求的全部隐含要求。普通科研问答继续需要证据和人工判断。
- 真实外部集群、真实湿实验、客户部署、文献科学结论及更高并发负载未在本轮重新验收。原版全局功能的回归结果与本次定向真实运行，应分别阅读。
