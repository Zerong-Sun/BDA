## 结论

默认路径已调整为“创建项目 → 明确目标 → 文献与证据 → 实验方案 → 预览确认 → 执行与结果”。新手可以手动创建项目，继承管理员配置的模型，逐步展开高级信息；熟练用户保留手工建图和配置入口。

本地验证覆盖了正常交接、错误提示、权限、预览变化与并发提交。当前模板目录不能覆盖任意科研问题，平台应明确显示缺口；模型输出需要核查。真实模型质量、客户集群连通性及外部作业回收仍属于部署验收，不能由通过本地测试推定。

## 修复清单

P1 表示可能导致错误作业、跨项目配置或关键流程失效；P2 表示交互、恢复、诊断或维护问题。以下条目均已修复。

| 编号 | 维度 | 级别 | 问题与完成的修复 |
| --- | --- | --- | --- |
| R01 | 需求完整性 | P2 | 手动建项负担过重：名称、类型、目标、约束构成默认入口，AI 任务书改为可选；首页突出下一步。 |
| R02 | 需求完整性 | P2 | Research 信息入口混杂：归为目标与问题、文献与证据、实验方案、决策记录四区；文献、结构和数据保留二级入口及旧链接兼容。 |
| R03 | 需求完整性 | P2 | 实验小工具依赖项目：增加独立工具箱，支持无项目计算和仪器预览，选项目后显式保存。 |
| R04 | 需求完整性 | P2 | 时间线决策信息堆叠：复用可折叠决策卡片，展示当前状态，按需展开推理与证据。 |
| R05 | 逻辑正确性 | P1 | 不同 AI 入口选择模型不一致：任务书、对话、后台任务、中文检索和路线推荐使用统一选择规则；显式失效配置不自动换模型。 |
| R06 | 逻辑正确性 | P1 | 工作流模板交接丢失参数与绑定、推荐失败仍套首个模板：保留服务端方案，只使用有效推荐，缺插件或输入声明错误时阻止直接应用。 |
| R07 | 逻辑正确性 | P1 | 脚本预览与真实 SSH 暂存方式不一致：预览复用执行渲染器，保留实际 staging 配置，静态检查明确未验证实时连接。 |
| R08 | 逻辑正确性 | P1 | 运行按钮直接提交、重复操作可重复创建作业：增加预览确认；提交加工作流行锁、版本校验、状态检查和幂等重放。 |
| R09 | 边界情况 | P1 | 仅工作流版本不足以锁定审核内容：新增脚本指纹，覆盖插件声明、参数、输入和执行站点；缺漏或变化返回 412，提交期间锁定插件声明再保存快照。 |
| R10 | 边界情况 | P1 | 切换项目后未保存的模型名和密钥草稿残留：按项目重建设置表单；服务端拒绝绑定其他项目的 BYOK provider。 |
| R11 | 边界情况 | P1 | 酶、甜味蛋白等类型误用 binder 路线：过滤不适用的模板，明确提示自定义工作流，不把缺少覆盖伪装成可运行方案。 |
| R12 | 边界情况 | P2 | 插件参数顺序规则格式错误引发异常：验证规则结构并给出明确 blocker，不再返回未处理错误。 |
| R13 | 边界情况 | P2 | 中文检索、空任务书、无效模型 JSON、虚构模板或证据 ID 被当作可继续结果：转换与结构校验失败时明确报错，不自动推进。 |
| R14 | 边界情况 | P2 | 预览被拒绝后页面保留旧缓存：刷新脚本预览，等待完成后由用户重新确认，避免反复提交同一份过期脚本。 |
| R15 | 代码质量 | P2 | 指定组织后仍额外查询组织列表：直接使用已知组织，减少请求及额外失败点；修正路线集合类型使 mypy 通过。 |
| R16 | 代码质量 | P2 | 模型选择、脚本审核和临时分析逻辑重复：提取共享函数；修正任务响应递归，检索提前失败时释放 HTTP client；同步 OpenAPI 与生成 SDK。 |
| R17 | 测试覆盖 | P1 | 并发提交只有内存数据库证据：增加两会话真实 PostgreSQL 回归，分别验证同一与不同幂等键只产生一份 submission、job 和派发事件。 |
| R18 | 实际运行结果 | P1 | 生产环境可能采用未验证的插件声明或节点镜像覆盖：生产强制运行证明与声明一致，预检阻止未经验证的覆盖；明确不能由模型保证任意脚本可运行。 |
| R19 | 实际运行结果 | P2 | 仪器预览请求超过通用网关上限：限制原始文件 12 MiB、归档展开 64 MiB，Nginx/Helm 对精确预览路径允许 17 MiB 请求体。 |
