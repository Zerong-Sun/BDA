## 逻辑正确性与边界情况

复核了旧客户端用户意图授权与显式任务范围的区分、子任务权限收窄、内部交接与领域写入的边界、MCP 权限撤回、乐观版本控制、幂等提交以及脚本预览指纹。既有和新增回归共同覆盖正向行为与拒绝路径。升级测试验证既有用户记录保留，而不只检查空库建表成功。

## 代码质量

复用现有迁移、领域服务与生成 API 契约。预览失效由输入快照决定，避免异步返回覆盖当前状态；归档正文仍按原始 SHA-256 验证。检查包括 Ruff、mypy、ESLint、生成契约差异、文档链接、插件目录和数据流矩阵。

- 浏览器：默认页面矩阵 74/74；工作流 UX 10 个场景通过。

所有数据库验证使用独立测试库；浏览器矩阵使用版本化接口桩。真实 HTTP 检查通过实际启动的服务完成认证与持久化读写，验证脚本、请求状态记录和服务日志保存在本次本地复核档案。

## 2026-09-14 运行版本复核补充

实际登录入口曾运行旧工作区的前端；该版本的 Research 使用七个顶层标签，而主线保留了目标与问题、文献与证据、实验方案、决策记录四大项。仅通过主线 CI 不能证明用户入口已经运行该版本，运行入口与构建提交必须单独核对。

进一步比较运行服务的 OpenAPI，发现它只有 194 个路径，主线的 15 个新增路径尚未部署，包括 bots、任务服务、MCP 和协作交接。路径数量代表契约差异，不代表功能缺失数量。

原部署数据库使用 `0057_plugin_output_routing`、`0058_staged_port_paths`、`0062_proteinmpnn_parser` 的旧迁移链。复核补齐这三个编号，并将对应的新编号改为汇合节点，保持既有数据变换只执行一次；升级回归扩展到八个既有状态，包含已经部署主线 `0064_public_integration` 的情况。实际部署前须先备份数据库，并在恢复副本上核对升级与原记录保留。
