## 完整的软件路径

从 **工作台 → 项目学习** 进入，或访问 `/#/learning?project=<UUID>`。前置对象是研究目标、候选序列、已上传的原始实验文件。界面提供酶性质和结合分子测定起始模板；研究者必须填写实际条件，模板不证明活性、结合或功能。

1. **冻结契约。** 测定方法、单位、条件不可变。Study 冻结研究目标版本、测定、方向、阈值、币种、批次预算、候选数、轮次上限、序列长度/禁用片段/域外约束。改变目标或约束创建新 Study，`supersedes_id` 保留修订关系，旧建议不能继续交接。
2. **记录实验。** 单条录入或 CSV 导入，保存原始文件、候选、批次、生物学重复、技术重复、样本角色、质控说明、测量时间、家族标签和显式状态。失败、缺失、上下检测限不转成零。数值单位必须与测定完全一致。
3. **冻结数据。** 每个训练快照至多 256 条结果，保存来源版本、文件 SHA-256、序列摘要、纳入及排除理由。撤回、对照、质控不通过、失败、缺失或删失值不作为精确训练标签。对照保留用于审查，当前不自动做板间校正。
4. **训练和审查。** 预先选择 KNN 或 ridge、验证拆分及可选校准。模型先处于 shadow，只有回顾误差优于冻结均值基线才允许人工提升。每个 Study 最多一个当前模型；被替换者退役。历史上已经提升过的模型可在来源仍有效时回滚，全过程保留审查理由。
5. **形成决策。** 对至多 256 个候选填完整实验估价，比较探索、利用、显式复测和停止。可选另一测定的模型做双目标 Pareto 排序。建议冻结模型、候选及学习状态；审阅写入项目时间线。模型、目标、结果、文件、证据或候选变更会阻止过期建议继续执行。
6. **交接与回流。** 对批准的建议建立实验交接单，复用 `campaigns` 的轮次和决策。可关联一个已有计算工作流。下载清单后按其中的 `batch_key` 录入或导入结果。一次接收必须包含该批所有未撤回记录，包括失败、缺失和重复，并覆盖每个选中的候选。回流同时写实验评价及操作者报告的实际费用。
7. **进入下一轮。** 前一批必须收到结果才能开下一批。冻结包含新结果的数据集，重新训练、审查、选批；真实数据变化会生成不同快照和模型。完成的回执不可改写，纠错使用撤回记录和新数据快照。
8. **保存认知和交付。** 区分事实、假设、冲突和未知；事实必须有实验或文件来源。撤回保留原记录，来源变动在界面标为待复核。完整学习交付包包含契约、测量、数据集、模型验证、决策、证据、批次和费用摘要；双目标建议包含第二模型及其训练证据。

创建建议、批准建议或生成交接单均不向实验供应商下单，也不预留财务预算。外部实验由被授权人员执行；工作流提交仍走现有预检、权限、预算和幂等提交路径。

## 实验导入契约

先通过项目文件上传原始 `.csv`，再选择它并执行“验证文件”；验证通过后才能在界面确认导入。服务器会重新校验整份文件，使用单一事务写入，不接受部分成功。

- UTF-8（可含 BOM），最多 2 MiB / 1,000 行。文件字节数及 SHA-256 必须与已完成上传的制品一致。
- 列名：`candidate_id,batch_key,replicate_key,replicate_type,status,value,unit,qc_accepted,note,family_key,observed_at,sample_role,measurement_key`。空模板可从页面下载；具体必填条件由同一 Observation schema 校验。
- `status`：`measured / failed / below_limit / above_limit / missing`；`replicate_type`：`biological / technical`；`sample_role`：`candidate / positive_control / negative_control`。
- `qc_accepted` 必须明确为 `true` 或 `false`；失败/缺失的 value 留空，检测限状态的 value 为检测限本身；时间必须包含时区。
- `measurement_key` 是原始文件内的孔位/测量唯一标识。同一标识重试返回原结果，改值重用返回冲突；不同技术重复应使用不同标识。未提供时按规范化内容去重，兼容早期预览记录。
- 候选、制品、测定和批次均须属于当前项目。重复列、未知列、错误列数、非法单位、非有限数字、跨项目引用及同文件重复测量标识会拒绝整份导入。
- 收到回执后不能再向该批追加新记录。原始重复请求仍可安全重试。测量撤回必须带理由和 `If-Match`，保留原值及操作者，不物理删除。

## 学习算法及限制

当前模型是可复算的序列基线，适合检验数据和决策闭环，尚未证明优于专业蛋白模型。

| 环节 | 实现与限制 |
|---|---|
| 特征 | 20 种氨基酸组成与缩放对数长度；1–10,000 个规范氨基酸。忽略残基顺序和结构。 |
| 重复聚合 | 同序列、批次、生物学重复内先求技术重复均值，再对生物学重复均值平均；技术重复多不增加独立权重。 |
| KNN | 至多三个最近邻、距离加权平均。保留参数和全部训练点。 |
| Ridge | 固定 alpha=1；每折仅以训练数据中心化、缩放和拟合，截距不惩罚。没有在留出集上自动调参。 |
| 序列验证 | 整序列留一；至少四个序列组，每折至少三个训练序列。 |
| 家族/批次验证 | 至少三个组；一个测试序列的所有训练重复均被清除。家族标签由实验负责人提供，同序列标签冲突会拒绝。 |
| 时间验证 | 至少五个不同测量时间；最后约 20% 时间点留出，清除测试序列的早期重复；至少两条留出预测。 |
| 提升门槛 | 留出 RMSE 严格优于逐折训练均值基线。人工反复比较算法可能产生选择偏差，需要独立外部测试集。 |
| 默认不确定性 | 训练距离和验证误差启发式，不能解释为成功概率或校准区间。 |
| 可选区间校准 | 仅序列/家族验证、至少 20 个独立组。按固定无标签散列分组，留出至少 9 组用于 split conformal；校准标签不参与训练、预处理或提升门槛。家族使用组内最大绝对残差。取 `ceil((n+1)×0.9)` 顺序统计量生成名义 90% 区间。 |
| 区间解释 | 覆盖率性质要求组可交换、独立和预测器固定；自适应选批、分布变化及域内条件筛选均可能破坏该性质，不能保证每个被推荐候选达到 90%。域外不展示区间。 |

所有验证折、训练/测试序列摘要、预测值、校准组、误差和参数摘要都保存在模型中。旧 `composition-knn-v1` 记录仍可读取，新训练使用 `composition-{knn|ridge}-{split}-v2`（可选 `-conformal`）。校准样本仍算“已经测过”，不会被当作新候选再次推荐；明确选择复测除外。

## 下一批决策

显式复测优先占用预算，其次填探索配额，再按预测方向利用。按原始量纲做双目标 Pareto 支配比较，不把两种单位直接相加。域外预测在利用排序中降级，也可在冻结契约中完全禁止。所有选中、未选中和被约束排除的候选均保留理由。

选择同时服从每批预算、候选数、序列约束和可选单候选估价上限。默认排除已测及重复序列。到达轮次上限或预算无法覆盖任何候选会停止；启用“达到阈值停止”时，以冻结数据中的序列聚合实测值判断，包含校准留出观测。

这是有界、确定性的启发式选批，不是全局最优实验设计、可制造性评估或通用多目标优化器。金额是操作者提供的估价/回执，不代表供应商已报价、已付款或财务对账完成。

## 所有权、隔离与执行

| 对象 | 所有模块 | 约束 |
|---|---|---|
| 原始文件 | artifacts | 现有上传、权限、状态与 SHA-256 契约 |
| 测量及撤回 | experiments | 复用 ExperimentResult；保留原值和历史 |
| 研究问题 | research | 目标树与版本，Study 保存冻结引用 |
| 契约/快照/模型/建议/证据/交接 | learning | 七张版本化表；项目 RLS；有界计算 |
| 实验轮次/评价 | campaigns | learning 经 service 写入，不另造实验调度状态机 |
| 决策时间线 | timeline | 研究者审查后生成，有目标链接 |
| 自动执行 | autopilot / compute | 冻结授权、预检、幂等任务、持久化 outbox 和取消 |
| 操作者记录 | audit | 创建、冻结、提升、回滚、撤回、交接及接收 |

模型和数据不会自动跨项目共享。列表使用游标，客户端拒绝循环游标和超出交互上限的集合，不静默截断。测量/导入/接收需 `experiment` 权限，契约/训练/证据/决策需 `write`；建立交接需两者。审查、撤回和回流均要求实际看到的 `If-Match` 版本（缺少 428、过期 412）。

工作流 `job.settled` 事件现在通过 outbox 反馈给 Autopilot。只有整个 workflow 成功才结算阶段并推进；失败或取消会把 campaign 置为 blocked，等待人工接管或取消。重复、迟到事件不会重复推进。取消 campaign 会请求取消相关活动 job。工作流草稿不能由“标记完成”伪装为成功，必须在 Workflow 页面预检并提交。详见 [Autopilot 协议](AUTOPILOT_CAMPAIGNS.md)。

## 交付包和成本边界

单决策证据包包含该决策及主/次模型的测定、目标、数据、参数和摘要。Study 完整包包含历次记录、完整测量、当前学习状态摘要、批次回执和总成本。文件字节独立从 artifacts 导出，包内保存引用和校验信息；每类历史对象交互导出上限 5,000 条、当前测量 10,000 条，超限明确报错。

费用摘要区分批次估价、已报告实验费用和未回流批次；实际费用包括失败样本。当前不计入人工、云计算、税费、供应商发票，也不充当客户账单。客户服务还需约定周转时间、实验责任、数据使用权、交付频率和支持范围。

## 部署和恢复

`0072_project_learning` 创建五张学习表；`0073_learning_lifecycle` 增加证据和批次表、目标修订及停止配置。应用、Docker、Compose、Helm 和 CI 的 schema revision 同步为 `0073_learning_lifecycle`，OpenAPI 和 SDK 一并生成。

部署前备份数据库和对象存储。在隔离数据库验证 `upgrade head → check → downgrade base → upgrade head → check`。降级 0073 会删除新证据/批次表和修订字段；降级 0072 会删除其余学习记录，不能直接对有数据的环境执行。优先回退应用并保留数据库，真正还原数据须使用已验证备份。

旧预览数据保持可读；没有完整学习状态摘要的旧建议须重新生成，不能直接批准或交接。已部署进程需同步重启 API、scheduler、worker、beat，不能把 Git 合并当作运行环境已升级。

前端首次使用默认并发全量复跑时，候选页等待第四页数据的一秒断言超时；该文件单独复跑及四 worker 全量复跑均通过，未修改其产品逻辑或放宽断言。上述数量采用最终完整运行结果。

摘要算法为 SHA-256，输入是 UTF-8 编码的 `json.dumps(content, sort_keys=True, separators=(",", ":"), ensure_ascii=True, allow_nan=False)`。跨语言复核需使用相同 JSON 数值和转义表示，不能直接对美化后的下载文件计算文件哈希来代替内容摘要。

前端下载保留服务器原始 JSON 文本，避免 JavaScript 把 `10.0` 重写为 `10` 或改变指数表示。决策包和完整交付包校验 `content → checksum`；实验交接下载保留完整批次记录，校验 `manifest → digest`。三个浏览器下载文件均已用独立 Python 校验通过。

这些记录不构成并发负载达标、14 天稳定性、生产备份恢复或真实实验效果验收。发布审阅和主干合并遵循现有分支保护。
