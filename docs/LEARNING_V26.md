## 已实现的路径

从导航中的 **工作台 → 项目学习** 进入，也可访问 `/#/learning?project=<UUID>`。

1. 在 Research 中建立研究目标，在项目中准备候选序列和已上传的原始实验文件。
2. 定义不可变的测定方法、单位与条件。条件或方法改变时建立新契约，不混合量纲。
3. 冻结学习目标：研究目标版本、测定、优化方向、目标阈值、每批预算币种和最多候选数。
4. 录入实验结果：候选、来源文件、实验批次、生物学重复编号、重复类型、测得/失败/低于或高于检测限/缺失，以及质控依据。
5. 选择至多 256 条结果冻结数据集。快照包含来源版本、制品校验和、纳入和排除理由、特征版本与序列摘要。
6. 训练并审查基线。新模型先处于 shadow；只有回顾性误差优于均值基线才允许人工提升。每个学习目标最多一个 promoted 模型，替换时旧模型退役。
7. 选择至多 256 个候选，逐个填写实验成本，生成预算内的探索/利用批次。输出所有评分、选择和排除理由、训练域外标记及无法继续时的停止建议。
8. 对建议作出有理由的批准或拒绝。审批写入已有项目时间线并链接研究目标。证据包可下载为 JSON，独立检查数据集、模型参数、建议和整包摘要。

审批不会提交实验、调用模型提供商、预订预算或启动无人值守任务。实际执行仍由现有经过授权的工作流、实验及 Autopilot 服务管理。

## 数据与权责

| 对象 | 所在模块 | 所有权与约束 |
|---|---|---|
| 原始文件 | artifacts | 已有上传、权限、状态和 SHA-256 契约 |
| 测量事实 | experiments | 复用 ExperimentResult；learning 元数据不复制独立测量表 |
| 研究问题 | research | 复用目标树；Study 保存冻结版本 |
| 测定、学习目标、数据集、模型、建议 | learning | 项目隔离；五张版本化表；有界计算 |
| 人工研究决定 | timeline | 审阅后生成记录，链接原研究目标 |
| 审计 | audit | 创建、冻结、模型提升/退役、建议审阅的操作者与实体 |

LearningStudy 是优化契约，不另造 campaign 调度状态机。模型和数据集不会跨项目自动共享。删除研究目标后，冻结证据仍保存，相关旧建议不能被批准。每批预算是估算约束，不是财务预留；重复批准不会自动产生支出。

写入权限沿用项目权限：测定和实验结果需要 `experiment`，目标冻结、训练、建议与审批需要 `write`。只读和演示模式在 UI 禁用写入，后端仍独立授权。模型与建议审阅必须携带实际看到的 `If-Match` 版本，缺少为 428，过期为 412。目标、模型或候选变化会阻止旧建议被批准。所有学习表都有 PostgreSQL 项目 RLS；列表采用游标，客户端拒绝循环游标和超过交互上限的集合，而不静默截断。

相同测量请求、相同冻结数据集及相同数据集/算法训练会复用已存记录。锁定测定、学习目标或数据集以串行化相应的重复创建；模型提升先锁学习目标，避免并发提升两个当前模型。

## 模型究竟会什么

当前算法 `composition-knn-v1` 是一个透明、轻量、可复算的蛋白序列基线，不是新基础模型。

- 特征：20 种氨基酸组成及缩放后的对数长度。候选必须有 1–10,000 个规范氨基酸。
- 重复处理：同一序列内，先对同批次、同生物学重复编号的测量求均值，再对重复求均值。技术重复数量不会增加独立样本权重。
- 验证：至少四组不同序列；整组留一交叉验证。训练集均值是每次留出后的对照，避免把留出标签带入基线。
- 拟合：最多三个最近邻，距离加权平均。模型参数包含训练点、特征版本、验证误差和训练域半径。
- 不确定性：距离和验证误差的启发式量，不是校准置信区间、成功概率或实验可行性保证。
- 选批：先保留设定比例的探索名额，再在估算预算内按预测方向贪心选择。已测序列、重复序列和超预算/批次数候选会明确排除。域外候选在利用排序中降优先级，仍可能作为探索对象入选。

阈值保存在决策契约中供研究人员审阅，目前不驱动自动达标停止。算法不含残基顺序、结构、同源家族隔离、跨批次外推验证、多性质 Pareto 优化、实验噪声模型或全局最优预算求解。仅优于均值的交叉验证结果，不能证明优于专业蛋白模型，更不能证明临床或湿实验效益。

## 部署与回退

迁移 `0072_project_learning` 创建五张表，并设置项目索引、外键和 RLS。先在隔离数据库验证 `upgrade head → check → downgrade base → upgrade head → check`。常规生产回退应只撤回新迁移前的应用版本；**降级 0072 会删除学习记录**，必须先导出和备份，不应在有新数据的环境中直接降级。

应用、容器构建参数、Compose、Helm 和 CI 的 schema revision 必须一起更新。OpenAPI 与前端 SDK 已纳入相同变更。试用前需要应用迁移并部署该分支；创建分支或合并 PR 本身不会修改运行中的数据库。

## 验证与发布门槛

自动测试使用明确标注的合成测量，覆盖完整 HTTP 链路、跨项目引用拒绝、只读写入拒绝、游标、缺少和过期版本、重复请求、失败/缺失/删失值、错误量纲、证据和元数据不一致、目标和候选变化、模型退役及证据摘要。浏览器矩阵覆盖页面、语言、主题、键盘操作及表单向生成客户端提交的值。

合成测试与回顾性模型误差属于软件证据。2.6 正式验收还需要：

| 后续工作包 | 必须提供的验收证据 |
|---|---|
| 强项目模型与不确定性校准 | 固定基准、家族/时间/批次外推拆分、校准误差、资源成本，优于本基线 |
| 多性质与约束决策 | 性能、安全、可制造性、成本联合约束；可重放的备选与停止理由 |
| 跨轮实验回流 | 至少两个真实前瞻实验轮次，原始数据、失败样本、批次/重复与版本完整 |
| 可靠执行衔接 | 复用现有预算账本、操作幂等性、取消和恢复；授权后才调用实验提供商 |
| 知识更新与证据冲突 | 时间版本、证据来源、撤回传播及结论变化可审计 |
| LAAS 产品化 | 客户交付与数据边界、反馈周期、成本和效益实测；不以智能体数量替代结果 |
| 正式品牌与发布 | 名称审查、发布审阅、迁移备份、恢复演练、可观测性和真实客户验收 |

这些门槛达成前，页面明确标注 preview，不使用“世界最好”或“实验成功率已提升”等没有比较实验支撑的描述。下一阶段应先补家族/批次外推验证与真实数据回流，再扩展模型复杂度。
