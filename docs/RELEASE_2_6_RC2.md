# BigoBio · Iteravia 2.6 RC2

状态：发布候选版（prerelease），非正式生产版。

最后核验：2026-10-11。

权威范围：`v2.6.0-rc.2` 相对 RC1 的软件变化、安装升级、发布资产与验收边界。

数据来源：版本化源码、自动化回归、隔离 PostgreSQL 迁移检查及合成本地运行记录。

替代关系：作为当前候选版说明，替代 RC1 的版本入口；[RC1 说明](RELEASE_2_6_RC1.md) 保留其初始化方法、历史验证和恢复记录。[生产恢复要求](STAGING_RELEASE_AND_RECOVERY.md) 继续有效。

## 本版变化

- **浅色界面**：冷灰画布、白色阅读和操作面板、BigoBio 酒红主色与蓝绿色数据色。统一导航、项目卡片、Bot 对话、科研决策、论据卡片和实验工具，修复链接式主按钮文字对比度。详见[前端说明](FRONTEND_V2.md#10-浅色主题)。
- **文献与决策**：论文链接、原文摘录、定位与上下文、所需论点、支持或反驳的论据、解释和适用边界形成可复核记录；支持跨文献对照、来源匹配和导出。决策中心记录假设、备选方案、成功标准、反证条件和下一步触发条件。材料完整性不等于科学结论正确。
- **研究方法和扩展**：提供版本化科研方法包、工具与权限边界、扩展资格及就绪状态；明确区分已执行、可配置和计划接入的能力。完整研究交付包保留论据与来源。
- **学习与实验质控**：增加序列表示、推荐和验证选项，以及仪器分析的质控与审核记录。验证拆分、校准适用范围和原始测量来源保持可见。
- **独立实验工具**：14 项分子生物学与合成生物学常用工具按用途归类，包含分子量、浓度、A260/A280、稀释、拷贝数、离心及仪器数据预览；无需创建项目即可进入。公式、单位和适用条件随结果展示。
- **Bot 输出可靠性**：研究问答与实验计算分流；确定性计算保留多步结果、单位换算和必要条件。工具失败、预算跳过、模型截断及部分完成不再被模型的完成声明掩盖。详情见[六维修复清单](DEEPSEEK_OUTPUT_AUDIT.md)。

## 版本与兼容

候选产品标签为 `v2.6.0-rc.2`。现有包身份 `2.0.0`、`/api/v2`、`BDA_V2_*` 和目录名称不变。数据库 head 为 `0074_research_decision_contract`。

相对 RC1 的 `0073_learning_lifecycle`，迁移仅新增 `research_goals.decision_contract` JSON 列，旧目标默认 `{}`；不会自动补写或猜测研究标准。API、worker、scheduler、beat 与前端须使用同一候选版。发布来自开发分支，tag 不表示主干审阅或合并已经完成。

## 新安装

```bash
git clone --branch v2.6.0-rc.2 --depth 1 https://github.com/Zerong-Sun/BDA.git
cd BDA
```

在此 RC2 目录中继续执行 [RC1 安装说明](RELEASE_2_6_RC1.md#新的本地安装) 的配置初始化、Compose 启动、对象 bucket 初始化、scheduler 独立身份及管理员创建步骤；跳过其中的 RC1 clone 命令。配置和镜像默认值已经更新至 0074，无需手工修改 API 路径或包版本。

没有预置账户密码或模型 API Key。静态前端包需要提供 SPA 回退与 `/api/v2` 代理的 Web 服务；它不是可独立运行的完整平台。完整平台使用源码包与 Compose，首次登录后在项目模型设置中配置提供商。

## 从 RC1 升级

1. 暂停写入与新任务，保留现有配置、模型凭据和对象存储；记录当前代码及数据库 revision，备份数据库并验证可恢复性。
2. 在隔离的数据库克隆上验证 `0073 → 0074` 及 `alembic check`。既有目标的空决策契约表示尚未填写，不能据此判断研究失败。
3. 获取并检出 `v2.6.0-rc.2`，保留自己的配置。Docker 安装执行 `docker compose up -d --build --wait`；API 启动时应用迁移。宿主机安装需先执行 `alembic upgrade head`，随后重启全部服务。
4. 检查 `/api/v2/health/ready`、登录、原有项目与原始文件、文献论据、研究决策、学习记录及实验计算。全部 worker 和 scheduler 应报告 0074 schema。

回退时先停止新写入并使用已验证的备份恢复方案。0074 的 downgrade 会删除决策契约列；不要在含新研究记录的业务库直接降级。完整 upgrade/downgrade 测试仅在可销毁的验证数据库进行。
