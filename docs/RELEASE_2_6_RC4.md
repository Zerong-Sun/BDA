## 证据与项目隔离

文献用途分为直接证据、方法、相关背景、排除和待复核。论文视图、论点视图、计数与导出
遵循同一范围。重复出版物仍保留原证据卡和引用编号；不跨项目合并 DOI。
证据包核对项目和文献归属，附件下载核对项目归属。历史项目可通过经授权的链接访问，
查找失败时清空活动项目，不能自动切到上次项目。详情见[证据整理规范](EVIDENCE_CURATION.md)。

生成稿仍需逐条审核。题录核验不等于论点成立，摘要摘录不等于全文阅读，下载图片不等于目视审查。

## 安装与运维

使用 release 的 `SOURCE_COMMIT` 核对源码提交，并用 `SHA256SUMS` 校验源码归档。
按[安全工程规范](SECURITY_ENGINEERING.md)配置项目权限、无 RLS 绕过能力的 API 数据库角色、
LLM 出站允许列表、用户明确选择的模型和计算后端。公开部署不预选 DeepSeek 或其他提供商。
数据库迁移头为 `0078_design_memory`，升级前备份并按现有部署流程执行迁移。

软件先在公开仓库验证和发布，再由私有仓库的 `.bda-sync` 单向同步同一提交；不要将私有历史推入公开仓库。
合并前必须通过完整 CI、公开数据规则和代码审阅；通过后清理已整合的远程分支及重复 PR。
保留仍被工作区使用或含独有内容的本地分支。新提交必须继续运行隔离回归和契约检查。

## 验证与边界

本候选的最终检查结果以对应提交的 GitHub Actions 为准。RC3 的测试结果不冒充 RC4 的结果。
发布源码候选不等于更新某个正在运行的服务；真实客户部署还需核对运行版本、数据库角色与
实际模型/集群配置。未获得用户确认的启明登录会话不得自动重连。

安全插件的 Deep Scan 尚未完成：当前运行环境未提供其只读扫描 worker 要求的受管理文件系统
权限配置。该项不计入已通过检查，不能据此声称“全面扫描零漏洞”或保证永远不再发生问题。
