严重度为本次工程风险分级，不代表已经申请 CVE 或完成独立渗透测试。

| 编号 | 风险 | 已落实的修复 |
| --- | --- | --- |
| SEC-01 高 | Campaign 轮次和评价可关联其他项目工作流/候选 | 服务层验证双方项目，worker 重新核验并过滤跨项目数据 |

| SEC-14 中 | 非认证入口校验错误可回显密钥/完整研究输入 | 全部请求校验错误去除 input/ctx，保持字段位置和错误类型 |

| SEC-16 高 | 生产连接角色可能绕过数据库 RLS | Readiness 检查实际连接角色，superuser/BYPASSRLS 拒绝就绪 |

## 历史数据检查

新增只读工具：

```bash
PYTHONPATH=. python backend_v2/scripts/audit_project_isolation.py --admin-user-id <enabled-global-admin-uuid>
```

使用目标部署的受控运维环境执行，报告只含关系名和 UUID。PostgreSQL 使用只读可重复读事务；退出码 1 表示存在待复核关联，0 仅表示本次检查覆盖的关联在该快照中一致。脚本不自动删除、搬移或重写科研数据。

发布前应先备份，再执行审计，依据原始输入、任务归档和审计记录判断历史归属；修复历史关联后重新检查。源码修复不能证明过去产生的数据全部正确。

## 升级与配置变化

- 包身份 `2.0.0`、API `/api/v2` 和 `BDA_V2_*` 兼容保留；以新候选版本 tag 和完整 Git SHA 标识本次安全升级。候选标签不是生产验收证明。
- 模型 API 的新 `BDA_V2_LLM_ALLOWED_ENDPOINT_ORIGINS` 默认为空，模型出站将被拒绝。升级前必须明确填入已审核 HTTPS origin，然后重启 API、copilot/research workers。Helm 对应 `config.llmAllowedEndpointOrigins`。不要把 API key 填入 allowlist。
- 公开项目重新明确选择其可用模型。私有管理员显式默认项仍可使用；没有内置厂商偏好。
- Compose 的网页默认仅监听 `127.0.0.1:8080`。需要外部访问时显式设置绑定地址，并先配置 TLS 与客户部署边界。
- 启明/LSF 输出收集要求登录节点有 `python3`，配置无符号链接的真实 remote root。默认最多收集 10 GiB、10000 个输出文件；变更前评估容量，可通过对应 compute collection 设置调整。
- 用新公开源码构建镜像；迁移使用独立凭据，普通 API/worker 角色不得是 superuser/BYPASSRLS。部署前检查 readiness、旧会话拒绝、两个合成项目与两个账号、上传下载、SSE/MCP 和模型错误处理。
- 先保留数据库、对象存储备份和上版镜像 digest。失败时按恢复文档回退镜像；不得用降级数据库覆盖客户数据。私有部署通过单向同步取得软件，不发布私有 overlay 历史。
