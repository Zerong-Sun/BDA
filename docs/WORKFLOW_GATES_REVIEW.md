## 六个方面的验证范围

1. **需求完整性**：连接与执行绑定一致、三种筛选模式、上游标准、物理子集、结构区域、脚本导入与实际绑定、参数来源、历史派生和回滚均有对应实现。未知格式和缺少标准保持待配置，不推测放行。
2. **逻辑正确性**：检查从 collection 到 gate 到 dispatch 的冻结数据、结果身份、稳定排序、人工资格限制和独立分支选择。
3. **边界情况**：覆盖缺指标、空结果、缺原子、缺链、插入码、失败重试、重复放行、分支汇合、配置冲突和文件完整性。
4. **代码质量**：运行 Ruff、全后端类型检查、较严格的工作流类型检查、ESLint、前端类型构建、API／数据流／文档／公开数据策略检查。
5. **测试覆盖**：执行后端全套测试及覆盖率检查、前端全套单元测试、工作流浏览器场景；新增 PostgreSQL 与容器运行测试可按环境变量重复执行。
6. **实际运行**：构建生产依赖镜像；DSSP 从合成坐标测得无／单／双螺旋分别为 **0／1／2**，同时检查区域、缺链和缺原子；Python 筛选容器验证非 root、根目录只读、禁网和失败处理。独立 PostgreSQL 测试包含迁移升降级、RLS、并发放行和状态可见性。

## 可重复执行

常规检查使用仓库 CI 中的命令。额外的实际运行测试为：

```sh
BDA_GATE_TEST_DATABASE_URL=postgresql+psycopg://... pytest backend_v2/tests/test_workflow_gate_postgres.py
BDA_GATE_RUNTIME_IMAGE=bda-workflow-gates-review:latest pytest backend_v2/tests/test_workflow_gate_runtime_integration.py
```

数据库地址必须指向独立测试实例。测试自行创建并清理随机 schema／role。容器测试只生成合成坐标，结束后移除测试容器；不读取私人研究数据。

生产升级、批量修复和发布不属于本次运行验证。历史流程的实际迁移报告需在目标数据库执行修复工具后生成；本次检查确认工具的幂等性、草稿派生和回滚行为。
