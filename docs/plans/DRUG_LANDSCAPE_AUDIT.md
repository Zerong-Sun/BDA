# 专利与成药性功能：六维验证与修复清单

审计对象：`7d3ba5e1`（专利检索）、`0c4b1a30`（成药性评估）、`353dd60c`（市场格局）、
`c0cc506d`（前端 U3/U4）。日期 2026-09-15。

结论：发现 5 个问题（1 个会让运行卡死、1 个会给出误导数字、1 个报错指向错人、
1 个需求缺口、1 组未测边界），已全部修复。下面按六个维度记录，每条都写明证据。

**F4（需求缺口）**：成药性报告新增 `literature_signal`——本项目已保存的论文数、专利数与最近
若干条文献（带 document_id）。一条都没有时，报告直接写明"没有任何东西可被引用，请先做检索"。
措辞刻意保守：**保存不等于读过**，更不等于支持成药性，这一句写在返回值里而不是文档里。

## 二、逻辑正确性

**F2（误导数字）**：`trial_activity` 的 `late_stage` 原本只要任意一个分期取到就求和。
若 PHASE4 取数失败而 PHASE3 成功，结果会报"432 条晚期试验"——把"取不到"当成了 0，
正是该模块自己用 `phases_unavailable` 防的错误。现改为 PHASE3 与 PHASE4 **都取到**才求和，
否则为 `None`。

**F3（报错指向错人）**：`create_druggability_run` 在用户没给检索词时回退到靶点名，
但长度校验在回退之后，于是靶点名过长会报 `trial_term_too_long`——指责一个用户根本没传的参数。
现改为先校验用户传入值（`trial_term_too_long`），回退值过长单独报 `target_name_too_long`
并给出可执行建议；靶点无名则报 `trial_term_missing`。

**另修**：`assessment()` 的入参校验原本写在报告构造**之后**，等于形同虚设，现移到最前。

## 三、边界情况

**F1（运行卡死）**：`druggability_assessment` 原本只有 `try/finally`，没有 `except`。
一旦检索整体抛错（不是单个数据源失败——那些已经记成 gap），任务异常退出，
而运行状态永远停在 `running`：没有报告、没有错误、读的人无从判断该等还是重跑。
现捕获异常 → 状态置 `failed` → 写入一条说明失败原因的报告行
（`IntelligenceRun` 没有 error 字段，所以原因落在报告里，`read_assessment` 原样读得到）。

这个修复当场就抓到了一个真 bug：补丁初版在任务作用域里漏了 `druggability` 的导入，
触发 `NameError`，被新的 `except` 兜住并标记 `failed`——三个任务测试因此变红，
反过来证明了这条路径有效。已补导入。

**F5（未测边界，已补测试）**：闰日（2024-02-29 + 20 年落在非闰年）、无申请日、
日期格式非法、US 再颁（kind E）为授权、无法解码的 kind 码报 unknown、
单个分类对象与分类列表两种形态、外部 JSON 里混入非对象行、
Open Targets 对已映射 ID 无记录、`target` 非映射被拒、两种检索词长度错误。
