# 专利、成药性与市场格局：规划与分期

状态（2026-09-15）：P1 专利检索与格局、P2 成药性证据、P3 竞争格局均已实现。未做的部分写在各小节末尾。

## 为什么要做，以及为什么不能交给语言模型

平台的策略早就禁止模型给出专利、市场或监管结论：`policy.py` 不允许没有证据支撑的"专利风险"
"市场空白""监管状态"判断，`research_agent` 的质检还会按模式拦下"USPTO 检索未见""没有专利先例"这类说法。
这条规则是对的，但留了一个洞：**没有任何办法把证据交进来**。结果是专利和成药性问题要么被拒答，
要么只能靠模型的记忆回答——而那正是规则禁止的。所以"让语言模型统一处理"不完整不是措辞问题，
是结构问题：缺的是可审计的检索，不是更好的提示词。

本规划的原则只有一条：**每个结论都要能追溯到一次有记录的检索**（数据库、查询、时间、响应校验和），
用和论文完全相同的证据标签。拿不到数据的地方写明拿不到，而不是估一个数。

## 数据来源（均已在本机实测可达）

| 用途 | 来源 | 结论 |
| --- | --- | --- |
| 国内外专利 | Europe PMC 专利索引（`SRC:PAT`） | 可用，免 key。含 CN（五十余万条）、US、EP、WO、JP、KR；带局、种类代码、申请人、IPC/CPC、申请与优先权日、摘要。**不含法律状态。** |
| 专利（备选） | EPO OPS、Lens.org | 需要 API key（实测 403/401），留作配置后的补充，不是默认依赖 |
| 专利（排除） | Google Patents 非官方接口、Espacenet 网页 | 可访问但不是公开 API，不作为产品依赖 |
| 靶点成药性 | Open Targets Platform（GraphQL） | 可用。`tractability`（小分子/抗体/PROTAC 可成药性分档）、`drugAndClinicalCandidates`、`safetyLiabilities` |
| 临床管线 | ClinicalTrials.gov API v2 | 可用。按干预、阶段、状态计数 |
| 药物与活性 | ChEMBL | 可用 |
| 市场规模、销售额 | — | **没有可审计的免费来源**，不做数字预测 |

## P1 专利检索与格局（已实现）

- 专利走文献检索的同一条管线：`literature_search` 按来源参数化，`europe_pmc_patents` 运行在翻译之后加 `SRC:PAT`，
  每条命中存为 `source="europe_pmc_patent"` 的文献文档，带检索轨迹与带校验和的摘要索引。
- `researcher` 持有新能力 `patent-search`：`start_patent_search`（排队，需用户明确请求专利检索）
  与 `summarise_patent_landscape`（只读已保存的专利）。
- 格局按局、阶段（申请/授权/PCT/实用新型/外观设计）、申请人、IPC 小类、优先权年份与估算期限计数，
  结果自带限制说明：无法律状态、期限为"申请日 + 20 年"估算、非 FTO 意见、找不到不等于不存在。
- 顺带修复：`sequence-analysis`、`structure-interaction`、`patent-search` 三项能力此前不在默认能力集里，
  默认项目看不到；现已补上，并加测试防止再次遗漏。

**未做**：检索时按局过滤（需要新列与迁移，且中文查询在翻译时可能丢掉过滤条件——目前检索覆盖全部局，
按局查看在格局里筛选）；专利族合并；法律状态（需接 EPO OPS INPADOC，要 key）。

## P2 成药性证据（已实现）

实现：`researcher` 持有 `druggability-assessment`；`start_druggability_assessment` 在
`intelligence.druggability` 主题上排队，`druggability_assessment` 任务经 `EvidenceToolService`
（新增经审计的 POST，GraphQL 请求体写进审计）取回证据，存为 `IntelligenceReport` 与每段一条
`IntelligenceEvidence`（引用即检索审计，待审核）；`get_druggability_assessment` 读回。
靶点无 UniProt accession 时在排队前拒绝。对 PD-1（Q15116）的实测：映射到 ENSG00000188389，
26 个药物与临床候选（9 个获批），抗体模态以已获批药物为证据可成药，试验按阶段计数全部取到，无缺口。

**未做**：若指定候选物时合并序列成药性指标（下面第四条）——需要把候选物 ID 带进运行，留作下一步。

原计划如下，对一个项目靶点（有 UniProt / Ensembl 映射）排队一次评估，经审计的请求取回：

- Open Targets 可成药性分档（小分子、抗体、PROTAC、其他模态），逐项保留其证据来源名；
- 该靶点上的药物与临床候选及其最高临床阶段；
- 已知安全性风险（事件、效应、数据源、文献）；
- 若指定候选物，合并已有的序列成药性指标（糖基化、脱酰胺、氧化、游离半胱氨酸、疏水斑块、pI）。

结果存为 `intelligence_evidence`（每条带检索审计），报告只陈述证据与缺口，**不给单一"成药概率"分数**——
一个没有校准数据集支撑的百分比，会被读成它不具备的确定性。

## P3 竞争格局，而不是市场规模（已实现）

实现：同一次成药性评估里新增 `market_landscape` 一段（另存一条证据行，引用试验趋势与申办方两组检索审计）：

- **靶点上的临床格局**：获批药物数与各临床阶段分布（取自 P2 的 Open Targets 结果）。
- **试验登记趋势**：ClinicalTrials.gov 在服务端按研究开始年份计数，覆盖含当年在内的 8 年，当年标为未满一年；
  某年取不到就是 `None` 并列出，不画成低谷。
- **申办方构成**：最多取 5 页（每页 1000 条，只要申办方字段），按 ClinicalTrials.gov 自己的分类
  （INDUSTRY / OTHER / NIH…）计数并列出主要企业申办方；没取全就标 `complete: false`，不外推——
  来源的分页顺序没有说明，第一页不是随机样本。
- **专利申请趋势**：只用本项目**已保存**的专利的优先权年份；评估本身不会替人发起专利检索，
  没有已保存专利时在缺口里写明"先做一次专利检索"。

报告自带限制：这是竞争格局，不是市场预测，不估算市场规模、价格、收入或份额；登记数不等于研发项目数；
INDUSTRY 计的是企业主导的登记，不是投入；近年的专利因未公开而偏少。

**未做**：申办方跨页全量聚合超过 5000 条登记的靶点；按适应症拆分；上市药物的销售与定价（无可审计来源）。

原计划如下：

"市场前景"在没有可审计数据时只能诚实地拆成可数的部分：同靶点已上市药物与在研管线（按阶段、状态、申办方）、
临床试验数量随时间的变化、专利申请趋势与主要申请人。市场规模、定价、销售额一律不出数字，
报告写明需要哪类商业数据才能回答。

## 不做的事

- 不新增第七个 bot：名册刚从十二个合并到六个，专利与成药性检索归 `researcher`（它本来就负责外部证据）。
- 不输出 FTO、有效性或侵权判断。
- 不用非官方接口抓取专利网站。
