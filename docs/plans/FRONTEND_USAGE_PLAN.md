# 前端使用逻辑：诊断与分期

状态（2026-09-15）：U1、U2、U6 已实现；U3（作业与画布走事件流）、U4（研究目标状态乐观更新）、U5（附件可见、可移除）部分实现，各自"未做的那半"写在下面对应小节里。

## 为什么“有点纯 SaaS”

问题不在视觉，而在交互模型。当前前端仍是一套“记录系统”：每个去处只有一扇门，状态只存在于打开它的那个组件里，数据靠定时刷新追上服务器。研究工作的形态恰好相反——人知道自己要找哪个 Bot、哪个运行、哪几个残基，想直接说出来；工作被 Bot 在后台推进，人需要被告知而不是反复刷新；一个判断要能被转发给同事并原样打开。

审计时的具体证据：

| 症状 | 证据 | 后果 |
| --- | --- | --- |
| 每个去处只有一扇门 | 21 个页面分散在导航、工具菜单、项目选择器与成员栏里 | 知道目的地也得先找到入口 |
| 主工作面不可链接 | `Workflow.tsx` 有 15 个 `useState`、0 个 URL 参数；另外 8 个文件已经在用 `useSearchParams` | 刷新丢失选中的运行与节点，无法把“看这个节点”发给别人，后退直接离开页面 |
| 拉取而不是推送 | 非测试代码中 22 处 `refetchInterval`；`/jobs/{id}/events` SSE 只在作业抽屉里、且仅在作业可取消时使用 | 状态变化最多延迟一个轮询周期；闲置标签页持续请求 |
| 写入等服务器 | 全应用只有 2 处 `onMutate` 乐观更新 | 低风险、可撤销的操作也有明显停顿 |
| 动作与上下文分离 | 在结构上选中残基、在候选表选中一行后，要带着它去问研究团队，需要手动转述 | Bot 协作被降格为另一个聊天窗口 |

## 分期

### U1 全局跳转（已实现）

⌘K / Ctrl-K 与顶栏可见按钮打开命令面板，搜索页面、项目、团队成员。三条约束：只导航不执行（模糊匹配列表里按早一次回车不能开跑或确认草案）；只索引外壳已持有的查询，打开时不发请求；快捷键之外必有可见入口。路由表抽到 `lib/nav/routes.ts`，顶栏与面板共用一份。

### U2 工作面进 URL（已实现）

工作流页的运行与节点移入 `?run=`、`?node=`，由 `lib/nav/useSearchParamPatch` 读写：同一事件里的多次修改会合并而不是互相覆盖，函数身份稳定，无变化不导航。节点点击替换历史，切换运行推入历史。链接里的运行若不属于当前项目，回退到当前运行并提示可清除；页面自己创建或选择的运行豁免此检查，避免新建后运行列表尚未刷新时误报。切换项目清空运行与节点，但首次解析项目不清空，以保留链接带来的运行。

### U3 推送优先的实时状态（部分实现：作业与画布）

原计划是"一个项目级事件流"。查过后端后改了范围：现有 SSE 只有三条，且都是按资源的——
`/jobs/{id}/events`、`/copilot/.../conversations` 与 `/operations/{id}/events`，没有项目级流。
新造一条要动 outbox 与新端点，收益集中在作业上，所以先把**已有的那条用满**。

已实现：`useJobEventStream` 从"只看抽屉里选中的那个作业、且仅在可取消时"改成**看一次运行里所有在动的作业**
（上限 4 条并发，浏览器对同一 host 大约只给 6 条，超出的会排队却看起来是连着的），
事件到达时同时失效作业列表、该作业日志与**工作流图**——画布上的节点状态就是作业状态，
之前让它自己走 3 秒定时器，是"某一步早就跑完了但画布还是黄的"的原因。
连着流时轮询退到 15 秒地板，断流或被拒时回到 3 秒：
按 CLAUDE.md 的说法，轮询是地板，断流不是错误。

未实现：研究室 feed、Inbox、agent run 列表仍在轮询——它们等的是 worker 推进任务，
后端没有对应的流可听。要做需要先加项目级事件流，那是后端工作，不在这一轮。

### U4 低风险写入乐观化（部分实现：研究目标状态）

只挑了一处：`ResearchGoalsPanel` 的目标状态。它可撤销、不花钱、不触发平台之外的任何动作，
等一次往返买不到安全，只会让勾选看起来是坏的。`onMutate` 先取消在途读取再改缓存，
失败时把服务器那份放回去，`onSettled`（而不是 `onSuccess`）重新拉取——无论写入落地还是被回滚都要以服务器为准。
412 仍是那个有意思的情况：目标在别人手里动了，重新读，而不是坚持。

**没有**跟着一起改的，以及原因：新建与删除会改变"有什么"，一行先出现再消失比晚出现更糟；
热点集的确认/否决会把 `agent_proposed_human_confirmed` 写进记录，属于决策不是偏好；
提交运行与确认草案要花钱。这些保持服务器确认。

### U5 带着上下文找团队（部分实现）

实施时发现“带上下文”的通道其实已经存在：研究工作区的“问 Copilot”与结构对照会把所选实体 ID 写入 `copilotSelectedEntityIds`，Bot 页把它们作为 `entity=` 随消息发送，后端 `research_context.build_context` 按 ID 优先取回（项目、主靶点、综述与发现、图谱节点与边、文献、结构、方法、数据集、文献证据）。缺的是**可见性**：附件随消息无声地走，人看不到团队将要看什么，也无法拿掉。

已实现：研究室输入框上方显示“附带”条，逐项列出名称（选择它的页面知道名称时；否则显示 ID，而不是隐藏）并可单独移除；发送后按原逻辑清空。名称只用于展示，服务器从不读取。

未实现：工作流节点、候选、结构热点残基集合目前不在 `build_context` 可解析的类型里，直接附带会被静默忽略。先扩展后端可解析类型，再在这些页面提供附带入口，否则界面会显示一个团队看不到的附件。

### U6 画布键盘操作（已实现）

React Flow 已让节点可用 Tab 聚焦，并在 Enter/空格时选中——但只在它自己的 store 里，从不调用 `onNodeClick`，于是键盘用户能高亮节点，检查器和 URL 却都不知道。现在节点选择变化会上报给页面（写入 `?node=`、打开检查器），画布上按 Esc 清除选择（节点内输入框里的 Esc 仍归输入框），`?node=` 反过来高亮画布上的节点，链接或刷新进来的节点也可见。

只上报“选中”，不上报“取消选中”：点击连线时 React Flow 会顺带取消节点选中，若上报会把刚选中的连线一并清掉。方向键不改作节点间跳转——React Flow 已用它移动选中的可拖动节点，两者冲突。

## 不做的事

- 不生成 Bot 之间的虚构对话；研究室只渲染真实的交接、子运行与决策记录。
- 命令面板不承担动作执行；需要确认的动作留在各自页面。
- 不为“更现代”而更换组件库或路由方案。
