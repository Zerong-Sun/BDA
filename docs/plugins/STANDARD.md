# BDA 插件解释与使用规范 v1

版本：2026-09-15。适用于模型插件、方法插件、历史版本和 authoring 草稿。规范管的是文档与证据质量；文档验收通过不等于程序已经接通或完成科学验证。

## 1. 必须先说明身份和证据边界

每个插件应有独立手册，标明 plugin_key、版本、启用状态、BDA 声明校验、运行证据日期/任务/声明指纹，以及上游仓库、固定 commit 或 release、读取日期。区分三类版本：上游版本、部署环境实际版本、BDA 包装版本。未知的实际版本写“待运行核验”，不得从容器名或标签推定。历史版本和草稿独立列出差异。

运行状态必须分别报告：enabled（是否启用）、validation_status（声明是否有效）、runtime_validation_status（数据库登记状态）、runtime_validation_is_current（证据是否匹配当前声明）。只有最后一项为真且输出、参数确实得到验证，才可写当前声明已运行验证；旧任务的成功只证明对应旧配置。

## 2. 每种功能模式必须有一张使用配方

记录用途、适用对象、必要输入、关键参数示例、预期输出、检查方法、约束、参考来源。状态使用 declared（声明接入，运行另查）、configuration_only（配置文件层支持）、not_exposed（上游支持但当前 BDA 没有完整入口）、unverified（实现或映射未核验）。另写上游是否支持及版本依据，不能把上游支持直接写成 BDA 可运行。

示例必须注明是 BDA 参数片段、上游配置片段还是独立命令，是否完整可执行。示例里的占位路径、链号、残基范围需由真实输入替换。RFdiffusion 的从头生成、motif scaffolding、binder、partial diffusion、对称生成分别写明长度/噪声/约束条件；不能用一个默认命令代表全部模式。

## 3. 参数按四层分别解释

| 层次 | 必须记录 | 禁止混淆 |
|---|---|---|
| 用户输入 | key、类型、含义、单位、默认值及来源、允许值/范围、适用模式、互斥/依赖、示例、BDA 字段名 | 默认值不等于推荐实验值；未声明默认不写成 0 |
| 命令与配置映射 | CLI flag/JSON/Hydra 键、BDA 别名、适配器、命令是否消费、覆盖优先级 | 表单有字段不代表已传入；目录/容器设置不等于科学参数 |
| 自动生成与派生 | staging 路径、最终 argv/config、种子分配、样本编号、链/残基映射、资源、文件哈希、所用权重和数据库版本 | 样本编号、FASTA header、链/残基编号不是氨基酸序列 |
| 结果参数 | 字段名、定义/公式、单位/尺度、方向、计算范围/对齐方式、生成条件、缺失语义、原始文件位置、解释边界 | 模型置信度不是结合亲和力；能量分数不是直接测得的自由能 |

每个参数解释需有可追溯来源，不允许仅将下划线拆成词。嵌套 JSON、列表和对象写出结构和至少一个例子；可扩展的任意 JSON/XML 不能声称有限列表覆盖全部自定义键，必须提供扩展键解释规则和上游 schema 入口。

默认值分开记录：上游默认、历史 library 默认、当前 BDA 表单默认、包装器 fallback/强制覆盖。没有调用参数时究竟采用哪个默认必须看最终命令。限制、单位、枚举必须匹配对应版本。

BDA 的普通命令模板只会把允许名称的标量导出为环境变量；布尔值在现有生成器中为 true→`1`、false→空字符串，数组/对象不能假设会自动成为 CLI 参数。包含点号/冒号的键及结构化输入需专用 adapter 或配置文件；以实际版本代码为准。必须检查 bash 的 `${x:+...}`、`${x:-...}` 对 false/空值的影响。

## 4. 输出与科学解释

保存全部原始输出列，不只挑好看的分数。解析器未识别的列仍保留，标“未解释”，并在该版本提交筛选证据前补定义；不要删除。记录成功/失败样本数、缺失项及原因、全部 seed/重复、均值和离散度；不同权重、长度归一化、采样次数和受体构象的结果不得混排。

特别要求：pLDDT 必须说明 0–1 或 0–100；PAE 必须注明 Å 或代码归一化尺度；RMSD 必须说明参与原子、链/残基映射和对齐参考；TM-score 必须说明归一化长度；MSA 记录原始深度、有效深度计算方法、配对/未配对状态，未生成 MSA 不可填 0 冒充测量。Rosetta REU、InterfaceAnalyzer dG_separated、稳定性 ΔΔG 与结合 ΔΔG 分开；Boltz 等亲和力输出注明训练/适用对象，不能扩展为通用蛋白–蛋白 Kd。

FASTA 序列行默认只接受标准氨基酸字母；非标准残基、X、链分隔符等依据工具逐项声明。数字只能出现在 header/编号元数据中，不能塞入纯蛋白序列。结构文件应与序列、链映射、输入哈希一一对应。

## 5. 使用步骤和失败处理

依次：确定科学问题与模式 → 选择精确版本 → 检查输入内容/链/残基/配体/缺失原子 → 设置模式参数 → 预览最终命令和配置 → 检查资源及运行状态 → 运行 → 核对参数实际被读取、全部声明输出及科学有效性 → 归档。文档审阅不触发计算。

列出常见失败、诊断日志和修复范围，例如参数未传、JSON 未改写、缺数据库、输入目录多文件选择不确定、空输出、None 被当成 0、非法输出尺度。若参数不生效，应写明确缺口与验收条件，不能给用户一个看似可运行的配方。

## 6. 维护、审阅和上传

机器可读 profile 放在 `docs/plugins/profiles/*.json`；生成的手册在 `qm-scripts/plugins/<slug>/REFERENCE.md`。旧 README 是集群操作说明，两者互链。每次更新必须附当前注册表快照、参数库来源及摘要哈希。生成器必须检查所有注册键/版本及已知 library/BDA 参数的覆盖、解释非空、来源引用和模式引用。

文档维护命令：

```bash
python3 qm-scripts/plugins/build_reference_docs.py --write
python3 qm-scripts/plugins/build_reference_docs.py --check
python3 qm-scripts/plugins/generate_docs.py --check
```

发布前由另一审阅者抽查模式关键约束、默认值来源、参数映射、结果尺度与解释、禁用/草稿状态及未解决缺口；机械覆盖不替代科学审阅。修订清单与已知缺口一起上传。上传后记录 BDA artifact ID、对象版本及 SHA-256，验证对象原始字节。文档更新不得篡改已冻结的计算 manifest 或重置/伪造运行证明。

## 7. 本轮覆盖口径

“完整”指 2026-09-15 注册表中每个键和版本、历史参数库以及手册明确列出的上游功能模式均有解释或明确的未知/未实现标记。它不是所有软件未来版本、Rosetta 任意 XML mover、任意第三方 checkpoint 和动态输出列的无限全集。新增模式/字段必须按本规范补 profile、来源与验证后才能加入受支持范围。
